# Инфраструктура проекта BASIS_TEST

Документ описывает инфраструктурное окружение проекта: Docker Compose,
единую точку входа (nginx), мониторинг (Prometheus / Grafana / Loki / Promtail)
и прод-схему blue-green.

## Обзор

Система состоит из двух типов компонентов:

1. **Сервисы приложения** — `api` (FastAPI, HTTP) и `consumer` (воркер:
   обработка платежей, публикация outbox, доставка webhook).
2. **Инфраструктура** — `db` (PostgreSQL), `rabbitmq` (брокер),
   `postgres-exporter`, `prometheus`, `loki`, `promtail`, `grafana`, `nginx`.

Все сервисы общаются внутри приватной сети Docker. Наружу смотрит **только
nginx** — единственный контейнер с внешним портом (по умолчанию `8601`).
Внутренние сервисы не публикуют порты наружу, управление RabbitMQ доступно
через nginx на поддомене `rabbitmq.localhost`.

## Docker Compose (локальная разработка)

Файл: `docker-compose.yml`. Поднимает всё сразу:

```bash
docker compose up --build
```

Сервисы:

| Сервис | Образ | Роль |
| --- | --- | --- |
| `db` | `postgres:17-alpine` | PostgreSQL, том `pgdata`, healthcheck `pg_isready` |
| `rabbitmq` | `rabbitmq:4-management-alpine` | Брокер с management-плагином, healthcheck `rabbitmq-diagnostics ping` |
| `api` | сборка из `Dockerfile` | FastAPI; при старте выполняет `alembic upgrade head` и запускает `python -m src.main` |
| `migrate` | сборка из `Dockerfile` | Одноразовые миграции `alembic upgrade head`, профиль `migrate` |
| `consumer` | сборка из `Dockerfile` | Воркер `python -m src.runtime.bootstrap.worker_main`; метрики на `8001` |
| `postgres-exporter` | `prometheuscommunity/postgres-exporter:v0.15.0` | Метрики БД для Prometheus |
| `prometheus` | `prom/prometheus:v2.55.1` | Сбор метрик, том `prometheus_data` |
| `loki` | `grafana/loki:3.3.2` | Хранилище логов, том `loki_data` |
| `promtail` | `grafana/promtail:3.3.2` | Сбор логов контейнеров через Docker socket |
| `grafana` | `grafana/grafana:11.6.1` | Дашборды, том `grafana_data`, provisioning из `deploy/grafana-provisioning` |
| `nginx` | `nginx:1.27-alpine` | Единая точка входа, внешний порт `8601` |

### Зависимости и порядок старта

- `api` стартует после того, как `db` стала healthy (`service_healthy`).
- `consumer` ждёт здоровых `db` и `rabbitmq`.
- `prometheus`, `grafana` и `nginx` зависят от прикладных сервисов.
- Миграции применяются автоматически при старте `api` (в проде/blue-green их
  тоже выполняет web-контейнер перед запуском приложения).

## Точка входа: nginx

Файл: `deploy/nginx/nginx.conf`. Маршрутизация по поддоменам `*.localhost`
(резолвятся в loopback без правки `/etc/hosts`):

| Поддомен | Бэкенд | Назначение |
| --- | --- | --- |
| `localhost` | static | Landing-страница со списком сервисов + `/healthz` |
| `api.localhost` | `api:8000` | FastAPI, `/docs`, `/metrics`, `/api/v1` |
| `consumer.localhost` | `consumer:8001` | HTTP-метрики воркера |
| `prometheus.localhost` | `prometheus:9090` | Prometheus UI |
| `grafana.localhost` | `grafana:3000` | Grafana (WebSocket для live-обновлений) |
| `loki.localhost` | `loki:3100` | Loki API (без веб-интерфейса) |
| `rabbitmq.localhost` | `rabbitmq:15672` | RabbitMQ Management UI |

Технические детали:

- `proxy_connect_timeout 5s`, `proxy_send/read_timeout 300s` — дашборды и графики
  не рвутся при долгих ответах.
- Для Grafana и RabbitMQ передаются заголовки `Upgrade`/`Connection`
  (WebSocket).
- Базовые заголовки `X-Real-IP`, `X-Forwarded-For`, `X-Forwarded-Proto`
  добавляются для всех бэкендов.

## Мониторинг

### Prometheus

Файл конфигурации: `deploy/prometheus/prometheus.yml`.

Targets:

| Target | Порт |
| --- | --- |
| API метрики | `api:8000/metrics` |
| Consumer метрики | `consumer:8001/metrics` |
| RabbitMQ (plugin prometheus) | `rabbitmq:15692/metrics` |
| PostgreSQL | `postgres-exporter:9187` |

### Grafana

- `deploy/grafana-provisioning` — автоматическое provisioning (datasources, dashboards).
- `deploy/grafana/dashboards` — файлы дашбордов (например, «Payments Overview»).
- Логин/пароль по умолчанию в dev: `admin` / `admin`.

### Loki + Promtail

- `deploy/loki/loki-config.yml` — конфигурация Loki.
- `deploy/promtail/promtail.yml` — Promtail собирает логи всех контейнеров
  через `/var/run/docker.sock` и отправляет в Loki.
- Логи смотрятся в Grafana → Explore → datasource **Loki**.

Примеры запросов Loki:

```logql
{container="basis-test-consumer-1"} |= "finalized: failed"
{container="basis-test-consumer-1"} |= "<payment_id>"
{container="basis-test-blue"} |= "error"
```

## Прод-схема: blue-green

Файл: `docker-compose.bluegreen.yml` (используется CI/CD, см.
`.github/workflows/master.yml`).

Ключевые отличия от dev-compose:

- **API разворачивается в двух экземплярах** — `web-blue` и `web-green`,
  которые поочерёдно выступают активным слотом. Каждый доступен на loopback
  (`127.0.0.1:8001` / `127.0.0.1:8002`) для host-nginx и оба имеют alias `api`
  в приватной сети (ротация без даунтайма для других сервисов).
- Все сервисы работают в **внешней сети** `webnet` (`BASIS_NETWORK`).
- Внешних портов нет: только loopback-порты blue/green (API) и grafana (`3003`).
  Наружу смотрит nginx, запущенный на хосте.
- `consumer`, `rabbitmq`, `db` и observability — статичные сервисы.
- Логи контейнеров маркируются именами `{APP_NAME}-blue` / `{APP_NAME}-green`
  для фильтрации в Loki.

Ротация blue-green выполняется обновлением одного слота, проверкой
healthcheck (`/health/liveness`) и переключением host-nginx на новый активный
слот.

## Запуск

### Всё сразу (с мониторингом)

```bash
poetry install
cp .env.example .env      # при желании поправить POSTGRES_*
docker compose up --build
```

Проверка: `http://api.localhost:8601/health/readiness` → `{"status":"ready"}`.

### Только приложение (без Docker для кода)

```bash
poetry install
cp .env.example .env

# БД в контейнере
docker run -d --name basis-pg \
  -e POSTGRES_USER=pyostr -e POSTGRES_PASSWORD=1503oreolMYSQL \
  -e POSTGRES_DB=demo_platform_db -p 5432:5432 postgres:17-alpine

poetry run alembic upgrade head
poetry run python -m src.main                  # API на :8000
poetry run python -m src.runtime.bootstrap.worker_main   # consumer
```

## Переменные окружения

Основные (полный список — в `src/config/settings.py`):

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `ENVIRONMENT` | `development` | `development` / `staging` / `production` |
| `POSTGRES_USER/PASSWORD/DB` | — | данные БД |
| `POSTGRES_HOST/PORT` | `localhost` / `5432` | адрес БД |
| `RABBITMQ_URL` | `amqp://guest:guest@localhost:5672/` | адрес брокера |
| `RABBITMQ_EXCHANGE` / `QUEUE` / `RETRY_QUEUE` / `DLQ_QUEUE` | `payments.exchange` / `payments.new` / `payments.retry` / `payments.dlq` | топология очередей |
| `RABBITMQ_RETRY_TTL_MS` | `5000` | TTL задержки retry-очереди |
| `RABBITMQ_MAX_RETRIES` | `3` | лимит повторов сообщения до DLQ |
| `OUTBOX_POLL_INTERVAL` / `OUTBOX_BATCH_SIZE` | `1.0` / `50` | цикл outbox-воркера |
| `WEBHOOK_SECRET` | `webhook-dev-secret` | секрет HMAC-подписи webhook |
| `WEBHOOK_RETRY_ATTEMPTS` | `3` | лимит попыток доставки webhook |
| `WEBHOOK_RETRY_BASE_DELAY` | `1.0` | базовый backoff (линейный) |
| `GATEWAY_MIN_DELAY/MAX_DELAY` | `2.0` / `5.0` | задержка эмулятора шлюза, сек |
| `GATEWAY_FAILURE_RATE` | `0.1` | доля отказов шлюза (0.0–1.0) |
| `METRICS_PORT` | `8001` | порт HTTP-метрик consumer |
| `PAYMENTS_API_KEYS` | `["dev-key"]` | ключи доступа `X-API-Key` |
